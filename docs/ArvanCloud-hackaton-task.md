# **بریف نهایی چالش: پلاگین ریسلری محصولات آروان‌کلاد در وردپرس**

## **۱. معرفی و هدف چالش**

هدف این چالش، توسعه یک پلاگین مستقل وردپرس است که به **«ریسلر»** امکان می‌دهد محصولات آروان‌کلاد را از طریق وب‌سایت خودش، با استفاده از API Key اکانت آروانش، به مشتریان بفروشد.

> **نکته کلیدی:** پلاگین باید بدون هیچ وابستگی به پلاگین‌های دیگر (مثل ووکامرس، ACF)، قالب وردپرس، یا حتی هسته‌ی وردپرس کار کند.

## **۲. دامنه محصولات (Scope)**

فقط پیاده‌سازی کامل **یکی از سه محصول زیر** الزامی است. شرکت‌کننده آزاد است هرکدام را که می‌خواهد انتخاب کند:

1. **سرور ابری (Cloud Server)**  
2. **شبکه توزیع محتوا (CDN)**  
3. **ذخیره‌سازی ابری (Object Storage)**

### **منظور از «پیاده‌سازی کامل»:**

پوشش کامل چرخه شامل:

* نمایش و قیمت‌گذاری در فرانت‌اند  
* ثبت سفارش  
* ساخت و تحویل (Provisioning) از طریق API آروان  
* اتصال Resource ID به کیف پول مشتری  
* محاسبه‌ی دوره‌ای مصرف  
* اعمال محدودیت (Suspend/Terminate) در صورت اتمام موجودی

## **۳. تعاریف کلیدی**

| اصطلاح | توضیح |
| ----: | ----: |
| **ریسلر** | مجموعه‌ای که با نصب پلاگین و اتصال API Key اکانت آروان خود، محصولات آروان را به مشتریان می‌فروشد. |
| **سهم ریسلر** | درصدی از مبلغ نهایی مصرف (پیش از مالیات بر ارزش افزوده) که آروان موظف است به ریسلر بپردازد؛ این درصد متغیر است و تا سقف ۲۰٪ قابل تعریف است. |
| **کنترل پرداخت** | بررسی وضعیت تمام پرداخت‌ها (در انتظار، موفق، ناموفق) به تفکیک هر مشتری. |
| **محدودیت‌ها** | امکان تعیین حداقل آستانه‌ی مصرف کیف پول توسط ریسلر، برای اعمال قطع موقت یا حذف سرویس. |

## **۴. معماری کیف پول پیش‌پرداخت (Pre-paid Wallet)**

معماری مالی پلاگین در ۵ گام خلاصه می‌شود:

1. **حساب مادر (در پنل آروان):** ریسلر اکانت اصلی خود را نزد آروان با مبلغی عمده شارژ می‌کند. هزینه‌ی تمام سرویس‌های ساخته‌شده یکجا از همین حساب کسر می‌شود.  
2. **کیف پول مجازی (در وردپرس):** مشتری وارد سایت ریسلر می‌شود و از طریق درگاه پرداخت ریسلر، کیف پول مجازی خود را در دیتابیس پلاگین (نه دیتابیس آروان) شارژ می‌کند.  
3. **ساخت و اتصال سرویس:** مشتری درخواست سرویس می‌دهد؛ پلاگین از طریق API آن را در آروان می‌سازد و Resource ID دریافتی را به کیف پول مجازی همان مشتری در وردپرس متصل می‌کند.  
4. **حسابداری خودکار (Cron Job):** پلاگین به‌صورت دوره‌ای (هر یک ساعت) مصرف هر سرویس را از آروان می‌خواند، سهم ریسلر را روی آن اعمال می‌کند و مبلغ نهایی را از موجودی مجازی کاربر در وردپرس کسر می‌کند.  
5. **کنترل و قطع سرویس:** به محض رسیدن موجودی مشتری به آستانه‌ی تعریف‌شده یا صفر شدن آن، پلاگین دستور قطع موقت یا حذف را فقط برای سرویس‌های همان مشتری به آروان ارسال می‌کند.

## **۵. امکانات و الزامات فیچر**

### **۵.۱ سیستم مالی اختصاصی**

* طراحی جداول اختصاصی وردپرس (**Custom Tables**) برای ثبت ریزتراکنش‌ها، لاگ مصرف و موجودی کیف پول هر مشتری — بدون استفاده از جداول پیش‌فرض محتوای وردپرس.  
* **Cron Job** برای فراخوانی مصرف از API آروان، محاسبه‌ی هزینه و کسر دقیق از کیف پول.  
* پیاده‌سازی فرمول سهم ریسلر (درصد متغیر تا سقف ۲۰٪) روی هزینه‌ی پایه‌ی آروان.  
* شبیه‌سازی شارژ کیف پول (mock payment، درگاه تستی، یا ثبت فیش) با اعمال صحیح مبلغ در کیف پول مجازی.  
* **تسویه‌حساب خودکار (Settlement CronJob):** تجمیع دوره‌ای هزینه‌ها و واریز خودکار سهم مصرفی به حساب آروان (یا شبیه‌سازی این فرآیند با API فرضی).

### **۵.۲ مدیریت مصرف و محدودیت‌ها**

* ایزوله‌سازی کامل داده‌های مالی، فاکتورها و کیف پول هر مشتری از سایر مشتریان (بدون تداخل در گزارش‌ها).  
* ارسال خودکار نوتیفیکیشن (ایمیل) هنگام رسیدن موجودی به آستانه‌ی تعریف‌شده توسط ریسلر.  
* اعمال خودکار Suspend/Terminate دقیقاً در لحظه‌ی صفر شدن موجودی مشتری.  
* **گزارش‌گیری شفاف:** نمایش تاریخچه‌ی تراکنش‌ها، پرداخت‌ها و ریزمصرف در پنل کاربری مشتری.

### **۵.۳ استقلال افزونه و امنیت داده‌ها**

* کارکرد کامل بدون نیاز به هیچ افزونه یا قالب جانبی (**Zero-Dependency**).  
* ذخیره‌سازی امن Access Token و کلیدهای API اکانت مادر (Machine User) در دیتابیس وردپرس.  
* پنل ادمین ریسلر برای ورود اطلاعات پایه (نام مجموعه، لوگو، اطلاعات تماس، درباره‌ما) و مدیریت یکپارچه‌ی تنظیمات پلاگین.

### **۵.۴ فرآیند فروش و اتصال به زیرساخت ابری**

* نمایش صحیح ویژگی‌ها و قیمت‌گذاری محصول انتخابی در فرانت‌اند سایت ریسلر.  
* ارسال موفق درخواست ساخت سرویس (Provisioning) به آروان بلافاصله پس از ثبت سفارش مشتری.  
* دریافت Resource ID پس از ساخت سرویس و اتصال دقیق آن به اکانت همان مشتری در وردپرس برای شروع محاسبات مالی.

## **۸. خروجی نهایی و الزامات ویدئوی دمو**

خروجی نهایی باید شامل **ویدئوی دمو** و **لینک گیت‌هاب پروژه** باشد.

### **الزامات ویدئو:**

* حداکثر **۵ دقیقه**.  
* شرکت‌کننده باید خودش محصول و نحوه‌ی کارکرد آن را توضیح دهد.  
* تمام قابلیت‌های پیاده‌سازی‌شده باید نمایش داده شوند.  
* تست و نمایش قابلیت‌ها هم در لپ‌تاپ و هم در موبایل.  
* نمایش یک سناریوی کامل از استفاده‌ی پلاگین (از نصب تا خرید و مصرف مشتری).
